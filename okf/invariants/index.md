# Invariant

* [Declared runtime imports — every runtime import is in its own package's manifest](declared-runtime-imports.md) - Every literal import in a workspace package's src/ names a Node built-in, a relative path, or a package listed in that package's own dependencies, peerDependencies or optionalDependencies — pinned by undeclared-imports.test.ts through ImportGraph.undeclared, which catches the devDependency and root-only imports that tsc and every in-workspace e2e test resolve but a consumer's install does not.
* [Package boundaries — process reads and forbidden imports](package-boundaries.md) - Each of sdk, engine, cli, mcp, ui, and reporter carries a boundaries.test.ts that scans its own src/ for forbidden process reads, imports, or tokens, pinning the platform-free core, the process-free engine, the two front ends' narrow process allowlists, and React/Ink staying off the ui root and the reporter's eager import graph.
* [Ranked layering — every workspace edge points strictly downward](ranked-layering.md) - Every workspace package is classified in the root layers.json, every runtime dependency edge points to a strictly lower layer, packages in one layer (cli and mcp among them) never depend on each other, and the carrier is the only top-layer package — enforced by WorkspaceLayering, not by convention.
* [Strict MCP tool inputs — every served input rejects unknown keys](strict-tool-inputs.md) - Every served MCP tool input rejects an unknown key at every object level, nested object, array element, and union branch, naming the accepted params instead of silently widening the query — pinned by served-schema-strict.test.ts.
* [Test-path classification — one rule for what is a discoverable test](test-path-classification.md) - classifyTestPath is the single pure rule for whether a path is a discoverable test file and, when not, what verdict it earns; the plugin's discovery walker and the CLI's check-test-path command both derive from it rather than re-implementing the layout rule.
* [The run-persist transaction never yields to the scheduler](persist-transaction-no-yield.md) - withPersistTransaction runs its whole SQLite write transaction in one event-loop turn by providing References.PreventSchedulerYield, so a second node:sqlite connection in the same process can never block the thread in the busy handler while the first holds the write lock; a test fails if the flag is removed, and nothing genuinely asynchronous may run inside the block.
