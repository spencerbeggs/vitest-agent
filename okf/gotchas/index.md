# Gotcha

* [A long-running vitest-agent MCP server keeps old modules after a relink or reinstall](stale-mcp-server-modules.md) - After a dependency relink or reinstall at the same path (a file: override, pnpm install after a branch switch, a lockfile regeneration), run_tests in a running MCP server runs stale code or fails every file with Worker forks emitted error and total 0, while a fresh process is green; nothing is broken in the tree, the server must be restarted.
* [An interactive exit can print "Hook cancelled" even though SessionEnd succeeded](sessionend-hook-cancelled.md) - Claude Code aborts an in-flight SessionEnd hook on an interactive exit and reports "Hook cancelled", which looks like a failed session-close write; the plugin's shim already detaches the real work so the write still lands.
* [Effect.provide reuses the inherited layer memo map](effect-provide-inherits-memo-map.md) - Providing a second layer inside a handler that already runs under a platform layer looks like it builds that second layer fresh, but a plain Effect.provide reuses the fiber's inherited MemoMap, so any shared module-level layer constant is a memo hit and the handler silently talks to the outer platform's service; pass { local: true }.
* [Reporter and MCP history looks wiped after an upgrade but sits orphaned under \~/.vitest-agent](legacy-reporter-data-root.md) - With XDG_DATA_HOME unset, the reporter and MCP server now open \~/.local/share/vitest-agent/\<key>/data.db, so run history they wrote to the legacy \~/.vitest-agent/\<key>/data.db looks lost after upgrading engine; it is still on disk, deliberately never read or migrated.
* [The lockfile's effect@4.0.7 was a deliberate toolchain bridge, not drift](effect-4-0-toolchain-bridge.md) - Retired: the build toolchain now runs on Effect 4.1, the root .pnpmfile.cjs that aliased it back to effect@4.0.7 is deleted, and the lockfile resolves one effect version; a second effect entry in pnpm-lock.yaml is no longer expected and is worth investigating.
* [XDG data-root fallback splits between the reporter and the hook routes](xdg-fallback-split.md) - Fixed by issue 422: with XDG_DATA_HOME unset, the reporter/MCP route and the hook/sidecar route now share one fallback data root, so they no longer open two different databases; the residual trap is the orphaned legacy file.
* [tdd_phase_transition_request is annotated Idempotent but is not](phase-transition-not-idempotent.md) - The tool declares Tool.Idempotent(true) yet its handler is not wrapped for idempotent replay, so a retried call opens a second phase transition instead of replaying the first.
