# Console modes

vitest-agent detects the current executor — human, agent, or CI — at run
start using environment variables. The resolved executor is looked up in a
per-executor matrix you configure on the plugin, and the matching slot
determines how the plugin handles console output for that run.

## Executor detection

The plugin checks for agent-specific environment variables first, then CI
variables, and falls back to `"human"` when nothing matches. Precedence is
agent, then CI, then human.

Agent variables checked include `CLAUDECODE`, `GEMINI_CLI`, `CODEX_SANDBOX`, `OPENCODE`, `AUGMENT_AGENT`, `CURSOR_AGENT`, `COPILOT_AGENT`, and a free-form `AI_AGENT`, among others.

CI is detected when `CI` or `CONTINUOUS_INTEGRATION` is set to any value other than `false` or `0` (so `CI=1` counts), or when `GITHUB_ACTIONS` is truthy — GitHub Actions is recognized even with `CI=false`.

## The console matrix

Configure the `console` option on `AgentPlugin` as a per-executor map:

```typescript
AgentPlugin({
  console: {
    human?: "passthrough" | "silent" | "stream" | "agent",
    agent?: "passthrough" | "silent" | "agent",
    ci?:    "passthrough" | "silent" | "ci-annotations",
  },
});
```

Each slot is optional. When a slot is omitted, the default for that executor
applies.

### Per-slot defaults

| Slot | Default | Rationale |
| --- | --- | --- |
| `human` | `"passthrough"` | Vitest's own reporters do the visible work |
| `agent` | `"agent"` | Compact markdown final frame |
| `ci` | `"passthrough"` | Vitest's reporters produce log-friendly output |

### Available modes

| Value | Available on | Behavior |
| --- | --- | --- |
| `"passthrough"` | all slots | Vitest's reporters keep ownership of stdout; the plugin emits no console output |
| `"silent"` | all slots | Plugin strips Vitest's reporters and emits nothing |
| `"agent"` | `human`, `agent` | Plugin strips Vitest's reporters and emits the plain-text run-shape view — the compact markdown frame an AI agent consumes |
| `"stream"` | `human` only | Plugin strips Vitest's reporters and renders a progressively-drawn, colored, animated Ink view of the run shape |
| `"ci-annotations"` | `ci` only | Plugin strips Vitest's reporters and emits GitHub Actions annotations |

## Stdout ownership

Any non-`"passthrough"` mode takes ownership of stdout. When the plugin
takes ownership it:

1. Strips Vitest's built-in console reporters (`default`, `verbose`, `tree`,
   `dot`, `tap`, `tap-flat`, `hanging-process`, and `agent`) from the
   reporter chain
2. Suppresses Vitest's native coverage text reporter

Non-console reporters are preserved regardless of mode. `json`, `junit`,
`html`, `blob`, and `github-actions` reporters continue to run and write
their respective files. Any custom reporters you have registered are also
preserved.

## Failure summary on stderr

When a run fails or is interrupted and the plugin owns stdout (`agent`,
`stream`, or `ci-annotations`), it writes a short plain-text failure summary
to stderr as the plugin's last stderr write (Vitest's coverage reporting can still write after it). `passthrough` and `silent` write none:
Vitest prints its own failures under `passthrough`, and `silent` is silent by
design. In `stream` mode the summary prints above the live view, so the view's
frames stay intact.

In `agent` mode the summary repeats the stdout failure list on stderr. That is
a deliberate trade: callers that discard stdout, such as `vitest doctor`, still
see the cause, and a shell that merges both streams sees the failures twice.

The summary has ANSI codes stripped and is capped at 15 lines, with a
`... N more` line when it is cut. It opens with a header such as
`vitest-agent: 3 failed tests in 2 files, 1 unhandled error`, then lists each
`FAIL <file> > <test>` with the first line of its error, any module-level
errors, and `ERROR` lines for unhandled errors. Tools that only capture the
tail of stderr, such as `vitest doctor`, therefore see the real cause of the
failure instead of nothing.

## Performance hints and slow post-run work

Because the plugin strips Vitest's own console reporters when it owns stdout,
it also takes over Vitest's performance hints (slow environment setup, slow
imports, slow transforms, and isolation overhead). It computes them in every
console mode so they reach `run.json` and `run_tests`, and shows them as
`info` entries in the suggested actions. Those actions are printed to the
console only in `agent` mode (the Actions list) and in `stream` mode (the
Actions block printed after the live view closes). In `ci-annotations` they
reach only `run.json` and `run_tests`, and under `passthrough` Vitest prints its
own hints. Hints are skipped in watch mode and
when Vitest's `experimental.diagnostics` setting turns them off.

The plugin also times its own post-run work (persisting results and scanning
coverage). The timing is always recorded in the report, but the console shows
it only when it is slow: at least 5 seconds, or at least 1 second and 10% or
more of Vitest's own duration. A slow run adds a `warn` suggested action naming
the persist and coverage-scan times.

## The stream mode

When `console.human` resolves to `"stream"`, the plugin mounts a live React
Ink view that draws the run shape progressively as the run advances, with
color and animation. The lifecycle is fully internal — there is no
live-view import to wire and no live-event callback to forward.
`@vitest-agent/reporter` owns the view's lifetime and `@effected/cli`'s
live renderer draws it. Each run's final frame stays in your scrollback;
the screen is never cleared. When stdout is not an interactive terminal,
the final frame is printed once instead, and `TERM=dumb` draws ASCII
glyphs. The suggested actions (including performance hints) print as an
Actions block once, after the live view closes at Vitest's close (in watch
mode, only at close and only the last run's actions), not inside the
animated frame.

## The agent mode

When the resolved mode is `"agent"`, the plugin emits a compact final frame
after the run completes. The frame includes:
- Pass/fail/skip counts
- Per-test classifications (stable, new-failure, persistent, flaky, recovered)
- A coverage snapshot against configured targets
- A footer pointing at the right MCP tool for the dominant outcome

## Forcing a specific mode

There is no global "force agent" toggle. Override a slot directly:

```typescript
// See the agent markdown frame from a human terminal
AgentPlugin({ console: { human: "agent" } })

// Suppress all console output in CI
AgentPlugin({ console: { ci: "silent" } })

// Draw the live progressive view on a human terminal
AgentPlugin({ console: { human: "stream" } })
```

## Per-run CLI override — `VITEST_AGENT_CONSOLE`

For a one-off CLI run where you need to see raw console output (for example,
when investigating a file flagged by `run_tests`'s `report.consoleLeaks`
signal), set `VITEST_AGENT_CONSOLE` before running Vitest:

```bash
VITEST_AGENT_CONSOLE=passthrough pnpm test
```

This overrides the plugin's resolved console mode to `passthrough` for the
active executor without touching the permanent config.

The override is checked against the slot for the executor detected on that run — not against the full set of modes. Each value behaves the same as its config counterpart, applied for one run only:

| Detected executor | Accepted `VITEST_AGENT_CONSOLE` values |
| --- | --- |
| `human` | `passthrough`, `silent`, `stream`, `agent` |
| `agent` | `passthrough`, `silent`, `agent` |
| `ci` | `passthrough`, `silent`, `ci-annotations` |

`passthrough` and `silent` are valid everywhere; `stream` is human-only and `ci-annotations` is CI-only. Matching is case-insensitive (`PASSTHROUGH` works). A value outside the detected slot's row is ignored, and a single stderr warning per run names the audience and lists what it accepts:

```bash
VITEST_AGENT_CONSOLE=stream pnpm test
# [vitest-agent:plugin] ignoring VITEST_AGENT_CONSOLE=stream: not accepted for the agent audience (accepts passthrough|silent|agent)
```

The run continues with the mode the matrix resolved, so an ignored override never fails a run — it just does nothing.

### Where stray console output shows up

| Surface | Sees stray `console.*` | Per-test attribution |
| --- | --- | --- |
| `run_tests` (MCP) | yes — `consoleLeaks` signal (counts + sample) | per file, per test where resolvable |
| Human at a TTY | yes — Vitest's own `stdout \|` / `stderr \|` lines | yes (TTY only) |
| Piped shell (default) | no — agent-shaped summary suppresses it | n/a |
| Piped shell + `VITEST_AGENT_CONSOLE=passthrough` | yes — raw passthrough | no (raw, unlabeled) |
